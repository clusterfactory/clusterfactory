# jenkins/ — plugin closure for the airgapped Jenkins controller

Upstream `jenkins/jenkins` image, unmodified (ADR 0001). Plugins cannot come
from the update centre offline, so they are resolved on the connected side
at package-create time and shipped as a **data-only OCI image**
(`jenkins/Dockerfile`: busybox + `/plugins`), which is Zarf's recommended
replacement for the deprecated `dataInjections`. An init container copies
them into the controller's plugin volume on every pod start.

- `plugins.txt` — the top-level plugins we want, pinned.
- `plugins.lock` — the full resolved closure (name + version), committed so
  a review can see exactly what changed. CI fails if it drifts from what
  `plugins.txt` resolves to.
- `plugins/` — the `.jpi` files, generated by `make plugins`, gitignored.
- `Dockerfile` — the data image; `make plugins-image` builds
  `ghcr.io/clusterfactory/jenkins-plugins:<package version>` into the local
  Docker daemon only. `zarf package create` runs both targets (`onCreate`).

The controller mounts the injected volume at `$JENKINS_HOME/plugins`, with
`installPlugins: []` and the update centre disabled. Gate 3 asserts every
plugin in `plugins.txt` reports `active` via `/pluginManager/api/json`.
