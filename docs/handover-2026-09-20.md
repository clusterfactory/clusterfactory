## What the VM taught us (already in ADRs / memory, listed so it is not lost)

1. The upstream init package *offers* an optional `k3s` component. Saying
   `y` on an RKE2 host installs k3s beside RKE2; its uninstall left
   iptables-legacy tables the host could not even list (EL9 has no
   `iptables-legacy`), every pod-network pod lost its route to the API
   server, CoreDNS went `0/1`, and only a reboot fixed it. The custom init
   package (ADR 0015) removes that slot. Until then: **always `zarf init
   --confirm`**, never interactive, on RKE2.
2. RKE2 ships no StorageClass. local-path-provisioner must be added before
   `zarf init` (ADR 0015 does it from the RKE2 manifests dir).
3. The broken-DNS cluster is exactly what 10a's `cluster-dns` check refuses
   on. rc.1 predates 10a; rc.2 will not deploy on such a cluster.
4. The SSM terminal wraps long lines and silently splits commands. Give the
   operator short lines or a script (`hack/vm-demo.sh` pattern); the
   runbook must be written that way.
5. `zarf` 0.76 warns that the legacy signature format is deprecated
   (`--features=bundle-signature=true`); bump Zarf and re-sign before
   `v0.4.0`.
